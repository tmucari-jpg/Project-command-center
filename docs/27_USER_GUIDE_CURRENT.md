# PCC — Guia Operacional do Utilizador

**Estado:** OFICIAL / CURRENT  
**Data:** 2026-10-13

## 1. Princípio

O PCC deve pedir apenas informação que ainda não conhece.

Fluxo esperado:
**sistema prepara → utilizador revê → utilizador corrige apenas excepções.**

## 2. Começar

Use:
- Resumo para visão geral;
- Novo projecto para criar/avaliar uma iniciativa;
- Objectivos para definir resultados;
- Projectos para acompanhar execução.

## 3. Executar

Hierarquia:
- Projecto;
- Entregável;
- Acção.

Quando seleccionar um Entregável numa Acção, o PCC pode inferir o Projecto.

## 4. Evidências

Seleccione preferencialmente a Acção.

O PCC pode inferir:
- Entregável;
- Projecto.

Registe apenas prova real:
- documento;
- link;
- resultado;
- comentário;
- referência.

## 5. Bloqueios

Associe preferencialmente o bloqueio à Acção.

O PCC reutiliza a hierarquia disponível.

## 6. Fábrica de Projectos

O fluxo guia a ideia até decisão.

Reveja:
- oportunidade;
- concorrência;
- diferenciação;
- riscos;
- evidência;
- validação;
- teste, se necessário;
- preparação final;
- decisão.

## 7. Teste

O PCC preenche metadados técnicos quando já existem na rota. O utilizador avalia principalmente:
- cenário;
- qualidade;
- factualidade;
- sucesso;
- correcção necessária.

## 8. Ideias

Capture rapidamente.
Estado inicial é automático.
Detalhes secundários podem ser adicionados depois.

## 9. Monetização

Registe:
- oferta;
- lead;
- movimento financeiro.

Etapas iniciais e alguns defaults são automáticos para reduzir esforço.

## 10. Regra de ouro

Se o PCC já conhece uma informação, não deve obrigar o utilizador a escrevê-la novamente.
